# agent_identity

## 作用

定义 Agent 的连续性与唯一性，回答“这是不是同一个 Agent”。

## 最小组成

- `agent_id`
  - 稳定且可迁移的唯一标识
- `canonical_name`
  - Agent 的标准名称
- `specialization`
  - Agent 的专业方向或岗位标签
- `mission`
  - Agent 长期稳定的职责描述
- `lineage`
  - Agent 的来源或演化关系标识，用于区分“升级后的同一 Agent”和“全新 Agent”

## 身份锚点

`agent_identity` 的关键，不只是“有哪些字段”，而是：

`哪些字段足以在不同运行环境、不同项目、不同时间点上，持续判断这是同一个 Agent。`

当前更合理的身份锚点包括：

- `agent_id`
  - 作为最强的稳定身份锚点
- `canonical_name`
  - 作为人类可识别的公共名称
- `specialization`
  - 作为专业角色边界
- `mission`
  - 作为长期职责边界
- `lineage`
  - 作为演化与继承关系锚点

这几个锚点共同作用，而不是依赖单一显示名称。

换句话说：

- 名称可以调整
- 技能可以演化
- 记忆可以增长

但如果身份锚点整体被改写，就不应继续视为同一个 Agent。

## 连续性判断

`agent_identity` 需要支持一个基础判断：

`这是同一个 Agent 的连续演化，还是一个新的 Agent？`

第一阶段不要求自动判定算法，但应先固定判断原则。

### 更可能属于“同一个 Agent”的变化

- `canonical_name` 有轻微调整，但核心角色不变
- `skill_pack` 被增强或修订
- `dynamic_memory` 持续增长
- `adapter_contract` 为适配新环境而扩展
- `lineage` 明确记录为同一 Agent 的版本演化

### 更可能属于“新 Agent”的变化

- `mission` 被根本改写
- `specialization` 被切换到另一种专业身份
- 原有 `lineage` 被中断或被声明为派生分支
- 角色职责和质量标准都发生本质变化

### 核心判断

第一阶段更稳妥的原则是：

- 角色增强、技能增长、环境适配，不等于身份变化
- 专业职责改写、使命转移、血缘断裂，才更接近身份变化

## 身份生命周期

`agent_identity` 也需要最小生命周期，但它的生命周期不等于记忆生命周期。

更合理的最小阶段包括：

- `established`
  - 身份已建立，可稳定引用
- `evolving`
  - 身份仍连续，但技能、契约或行为边界正在演化
- `forked`
  - 从既有 Agent 派生出分支，不再完全共享身份连续性
- `retired`
  - 该身份不再作为活跃 Agent 使用，但仍保留历史可追溯性

这里最关键的是：

- `evolving` 不等于新 Agent
- `forked` 才更接近新身份开始

## 非目标

当前阶段不定义：

- `agent_id` 的具体生成算法
- 身份自动比对算法
- 跨系统全局注册中心
- 权威签名或加密认证机制

这些都属于后续实现或治理层问题，不属于当前最小模型。

## 边界

`agent_identity` 只定义身份，不定义技能细节，不保存动态经验，也不承载运行环境状态。

若需要限制可见性或工作区专用性，应由独立的 scope 侧车或运行时绑定层处理，不要塞进 `agent_identity` 本体。

## 禁止混入

- 工作区路径
- 项目状态
- 临时任务上下文
- 后端配置
- 运行时学到的临时经验
